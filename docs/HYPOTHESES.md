# 座標復元: 試した仮説と結果

種類 9 の V×3 個の値（[FORMAT.md](FORMAT.md)）から頂点の座標を組み立てる規則を探した記録。

## 解決（正しい規則は FORMAT.md の「種類 9」）

以前の試み（下記 1〜6）が外れたのは、次の 4 点が同時にずれていたため。どれか 1 つだけ直しても合わない。

| | 以前の前提 | 正しくは |
|---|---|---|
| 値の並び | 頂点ごと (u, v, w) を V 回 | **軸ごと**（u を V 個、v を V 個、w を V 個） |
| 格納の順 | 走査で初めて触れた順、または `decode` の番号順 | **Apple の頂点番号**の順。境界は最初の三角形の角 1 から歩いて b−1 から数え下げる |
| 組み立ての順 | CLERS の順（三角形を作った順）に、新しい頂点をゲートから予測 | 完成したメッシュの**面をスタックでたどる**。各面の角 0, 1, 2 の順に隣を積み、取り出したときに積んだ側の面から予測 |
| 座標の意味 | 立方体の面の (u, v, 奥行き) か直交座標 | 面ごとの**経度・緯度（mrad）と距離の逆数**。面は立方体ではない |

見つけた手順:

1. 空の面（V ≈ 22）の値は、軸ごとに読むと 3 つ目の軸がすべて 0 になる（距離の逆数 = 0 = 無限遠）。軸ごとの並びと確定。
2. 軸ごとに読むと、どのメッシュでも 3 つの値だけが桁違いに大きく、y が −1220 でそろう（絶対値）。その位置は先頭が C なら 0, b−1, b で、L・R・S のメッシュではずれる。
3. Apple Flyover の C3M の Edgebreaker 変種の公開解析（retroplasma/flyover-reverse-engineering）を移植すると、その頂点番号の振り方で、大きな値の位置が 48/48 で最初の三角形の 3 頂点と一致した。ただし同じ解析の走査と符号（値を引く）では発散した。
4. 空の面で「全頂点が範囲 ±522 に収まり、向きが一貫する」予測の組を深さ優先で総当たりした。符号 + では解が見つかり（符号 − では 0 件）、各頂点の予測に使う三角形が一意に決まった。その並びから、走査の規則（角 0, 1, 2 の順に積む、取り出したときに決める）を読み取った。
5. この規則で 48/48 のメッシュが面の範囲にぴったり収まり、地面の平面・カメラ高・別走行との重なりで確かめた。

面の画像（MCP4 の種類 3、HEIC）を並べると、面は経度の帯と上下の帽子だとすぐ分かる。立方体の面を前提にした物差しを使う前に、画像を見るべきだった。

---

以下は解決前の記録。外れた仮説と物差しの落とし穴。

## 判定の物差し

| 物差し | 中身 | 注意 |
|---|---|---|
| 別走行の重なり | 中心（pano0）と、翌日の別走行で 1.7 m 離れた pano6 を ECEF に置き、最近傍距離 ÷ メッシュの広がりを見る。pano6 を 90° 回した対照と比べる | 絶対距離だけで見ると、スケールを小さくして雲を縮めるほど良く見える（下記 1） |
| 境界が閉じるか | 境界の頂点 0..b−1 はループなので、最後→最初の一歩も普通の一歩と同じくらいのはず | |
| 内側が境界の中に収まるか | 円盤なので内側の頂点は境界の範囲内にある | **いちばん厳しい。今後はこれを使う** |
| 浮いた頂点 | 隣のどの頂点からも中央値の 6 倍以上離れた頂点 | 領域ごとまとめてずれると見逃す（下記 6） |
| 発散の位置 | 冒頭 25% の広がりの 4 倍を超えた位置 | 冒頭から発散していると見逃す（下記 4） |

## 1. 単純な積み上げ（予測なし）

値を順に足し上げて座標とする。並び方 2 通り（頂点ごと・軸ごと）× 軸の入れ替え 6 × 符号 8 × スケール（0.001〜0.05）。

- 別走行の最近傍距離の最良は 0.37 m。**ただしスケール 0.001 で雲が約 3 m に縮んだため**で、2 枚は 1.7 m しか離れていないので、正誤に関係なく近くなる。無効。

## 2. 頂点の並び = 境界が先頭、続いて C の順

境界は差分で積み上げ、内側は予測（平行四辺形 a+b−o、中点、ゲートの頂点 a、直前の頂点）。

- 中点予測が最も形の整った三角形（辺の比の中央値 約 2.3）を作ったが、別走行の重なりは最近傍 / 広がり = 0.093、90° 回した対照との差は 1.4 倍しかない。
- 境界が閉じない: 最後→最初の一歩が普通の一歩の 12〜31 倍。**この並びは誤り。**
- 軸ごとの並びで読むと、23 頂点の面（面 4）では 3 つ目の軸の値がすべて 0。

## 3. 頂点の並び = 走査で初めて触れた順

最初のゲートの 2 頂点のあと、三角形の 3 つ目として初めて触れた順（`lookaround_mesh.first_touch`）。

- 境界の閉じ具合は 7.6〜8.4 倍まで改善（頂点ごと＋平行四辺形／中点）。まだ閉じない。
- 頂点ごと＋平行四辺形 a+b−o で、**境界の頂点は 3,336 個中ひとつも浮かない**。

## 4. 平行四辺形まわりの細部

- **成分の順番**: 3 成分が同時に崩れる（先に崩れる成分に偏りなし、13・16・12）。成分ごとの扱いの違いではない。
- **平行四辺形の向き**: a+o−b と b+o−a は冒頭から指数的に発散（座標の範囲が 1e19）。発散の位置の物差しでは「41 中 39 が最後まで無事」と出たが、冒頭から発散していたため物差しが働かなかっただけ。
- **直前の三角形を参照に使う**: a+b−o と変わらず。
- **丸め**: a+b−o は整数だけで計算できるので関係ない。
- **残差を 1 頂点ずらす**: 崩れる位置の前後でずらしても改善しない（41 中 40）。
- **例外表の値**: 最初に崩れる頂点の 37/41 は 1 バイトに収まった普通の残差。例外表の値はストリームの冒頭から問題なく使われている。

## 5. 崩れる頂点で規則を差し替える

最初に浮いた頂点だけ予測を差し替え、その先がどこまで組み上がるかを比べた（`experiments/probe.py`）。

- 最良: 中点 12/41、ゲートの頂点 a 11/41。一貫した答えなし。
- 崩れる頂点と普通の頂点の特徴の比: 「o が a・b より後に置かれた」4.9 倍（ただし崩れた場面の 22% のみ）、向こう側の三角形が L 3.2 倍、S 2.3 倍。単一の条件では説明できない。

## 6. 訂正: 「80〜92% が正しく組み上がる」は誤り

初めて触れた順＋a+b−o で、浮いた頂点の物差しでは各メッシュの 80〜92% が無事に見えた。しかし、

- 無事に見えた前半 60% でも、**内側の座標が境界の範囲の 5〜20 倍に広がっている**（最大 ±30 万）。円盤の内側は境界の中にあるはずなので、この段階で既に誤り。
- その前半 60% で別走行の重なりを見ても、最近傍 / 広がり = 0.15、90° 回した対照との差は 1.0〜1.4 倍。重なっていない。

## 解決前に挙げていた次の一手（結果）

1. 総当たり → 小さな空の面で、予測の組を深さ優先で探す形で実行し、これが決め手になった。
2. (u, v, 奥行き) の面座標 → 近かった。正しくは経度・緯度・距離の逆数。`0.001, 0.001, 1000` はその単位。種類 11 の `0.05` の意味は未確定のまま（組み立てには使わない）。
